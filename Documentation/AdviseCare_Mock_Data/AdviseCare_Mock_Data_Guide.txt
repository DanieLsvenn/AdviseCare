==========
1. HOW TO LOAD IT
==========

Step 1 - run AdviseCare_Database_Script.sql
- It recreates all 51 tables and inserts the mock data (about 3,400 rows across 47 tables; INDICATORFLAGS, CASEMESSAGEATTACHMENTS, TRANSCRIPTIMPORTBATCHES and TRANSCRIPTIMPORTFILES start empty).

Step 2 - start the API
- Use the master key of your environment (Encryption:MasterKeys / Encryption:CurrentVersion).

Step 3 - sign in as admin02@example.com (password 123456) and import the two demo accounts
   POST /api/Accounts/import (multipart/form-data, file only; POST /api/Accounts/import/preview shows the same checks without writing)
   - Columns: email, fullName, userName, facultyCode, role (exactly one role name: every account has exactly one role), studentCode, academicStatus.
     Staff rows leave studentCode and academicStatus empty; an empty academicStatus on a Student row means enrolled.
   account_import.xlsx (or account_import.csv, same rows)
   - 2 Student rows of faculty SE: ngophanthanhcong123456@gmail.com (Ngô Phan Thành Công, SE180099) and t3nt3nyulie@gmail.com (Nguyễn Như Thành, thanhcute, SE182739).
   - Invalid cell on purpose: row 3 academicStatus "eenrolled". Expect isSuccess = false, 1 error on row 3 and nothing created (all-or-nothing).
   - Fix it to enrolled (in the editable preview or the file) and import again: expect isSuccess = true and createdCount = 2.
   - Then send the linking emails (POST /api/Accounts/linking-emails); each person opens the link and signs in with that Google account (EX1).

Step 4 - import the student data values of the two demo accounts, Summer 2026 first
   POST /api/StudentData/import (multipart/form-data)
   columnMapping = { "studentIdentifier": "Student", "dataAttribute": "Data attribute", "value": "Value", "term": "Term", "validFrom": "Valid from", "subject": "Subject" }
   (the Subject column holds subject codes and is filled only for the per-subject attributes Attendance rate, Absent slots, Late submissions and Subject mark)
   1. mock_data_sum2026.xlsx (or mock_data_sum2026.csv)
      - 56 rows, valid from 2026-08-10: every active data attribute for both students (two subjects each for the per-subject ones:
        Công PRF192 and MAE101, Thành PRF192 and CSD201).
      - Invalid cell on purpose: Công's "Financial difficulty" is "no" (not true/false). Expect isSuccess = false with 1 error; fix it to false and import again.
      - Then expect insertedCount = 56; missing rows go to the other enrolled students (the mock ones), since they have no Summer values in this file.
   2. mock_data_fall2026.xlsx (or mock_data_fall2026.csv)
      - 48 rows, valid from 2026-11-12 (Công PRN212 and SWP391, Thành DBI202 and CSD201).
      - Left out on purpose, so they become missing rows: Công's Credits attempted, Library visits, English level, Receives meal support;
        Thành's LMS logins per week, Commute time, Scholarship status, Family income bracket.
      - Invalid cell on purpose: Công's GPA is "7,2" (a decimal comma is not a number). Expect isSuccess = false with 1 error; fix it to 7.2 and import again.
      - Then expect insertedCount = 48. Thành hits 4 active indicators: Low attendance (68 in DBI202 only, CSD201 is 80), Very low GPA (4.8),
        Two or more failed subjects (2) and Tuition overdue (true). Công hits none.

Step 5 (optional) - import the transcript PDFs of the two demo accounts (per-subject Subject mark and Attendance rate)
   In the web app: Admin > Academic results import (or POST /api/TranscriptImportBatches with files = the PDFs, then POST /{id}/commit).
   Transcripts folder:
   - Transcript_SE180099.pdf / Attendance_SE180099.pdf (Công): Summer 2026 PRF192 7.4 / 90 %, MAE101 6.6 / 86 %; Fall 2026 PRN212 7.5 / 88 %, SWP391 6.9 / 92 %.
   - Transcript_SE182739.pdf / Attendance_SE182739.pdf (Thành): Summer 2026 PRF192 5.8 / 81 %, CSD201 4.9 / 77 %; Fall 2026 DBI202 4.5 / 68 %, CSD201 5.6 / 80 %.
   - Every file also lists SWE201 as not started (no semester, no value): it is left out with a warning (skippedRowCount = 1).
   - Transcript_SE182739_invalid.pdf: Thành's grade transcript with DBI202 printed as 45 (a typo for 4.5).
     Upload it with the others: the file is invalid ("Row 3 (DBI202): grade 45 is not between 0 and 10.") and the batch cannot be imported (all-or-nothing);
     remove it in the preview and drop Transcript_SE182739.pdf instead.
   - Then importing the 4 valid files writes 16 values (2 subjects x 2 terms x 2 attributes x 2 students). If steps 4.1/4.2 were imported first,
     all 16 replace a current value (same numbers, newer rows; replacedCount = 16); otherwise replacedCount = 0.
   - The values show in each student's Private data tab (Academic results card and the data list) and, with consent, to their advisor.

Why the values are not in the SQL script
- STUDENTDATA values are AES-256-GCM encrypted with the student's attribute key, and that key is wrapped with the API master key.
- The import encrypts with whatever master key the running environment uses, so this works for every teammate and for MonsterASP.
- Seeded directly in SQL (no encryption needed):
  - Spring 2026 missing-value rows;
  - Spring 2026 erased rows with their destroyed keys and completed erasure requests;
  - 3 correction requests decided before the erasure (their values were cleared by it).
- After the import:
  - create pending correction requests through POST /api/CorrectionRequests (studentDataId, consentPurposeId, explanation, proposedValue);
  - pending erasures are created automatically when a student withdraws a consent of an attribute that now has a key;
  - indicator flags are raised by the server for every enrolled student whose latest value hits an active indicator.

==========
6. REGENERATING
==========

- The data is generated by a script with a fixed random seed, so running it again gives the same ids and values.
- The rows added on 09/11/2026 use fixed name-based ids (uuid5), so they stay the same too.
- Ask Claude to regenerate it after a schema change. Every row is checked against the script's constraints (NOT NULL, CHECK, FK, UNIQUE and the filtered unique indexes) and against the business rules before it is written.

==========
1. HOW TO LOAD IT
==========

Step 1 - run AdviseCare_Database_Script.sql
- It recreates all 48 tables and inserts the mock data (about 3,400 rows across 47 tables; INDICATORFLAGS starts empty).

Step 2 - start the API
- Use the master key of your environment (Encryption:MasterKeys / Encryption:CurrentVersion).

Step 3 - sign in as admin02@example.com (password 123456) and import the student data values, in this order:
   POST /api/StudentData/import (multipart/form-data)
   columnMapping = { "studentIdentifier": "Student", "dataAttribute": "Data attribute", "value": "Value", "term": "Term", "validFrom": "Valid from" }
   1. mock_studentdata_summer2026.xlsx
      - 1,056 rows, all valid (1,033 mock rows + 23 rows for student@gmail.com).
      - Some (student, attribute) pairs are left out on purpose, so missing rows are created for enrolled students.
   2. mock_studentdata_fall2026.xlsx
      - 1,037 rows, all valid (1,014 mock rows + 23 rows for student@gmail.com).
      - The Student column mixes emails, usernames and student codes: all 3 identifiers must work.
      - student@gmail.com gets Attendance rate 72, so the active "Low attendance" indicator (< 75) flags it.
   3. mock_studentdata_fall2026_update.xlsx
      - 37 rows: new GPA and Attendance rate values for 16 students (student@gmail.com included), valid from 2026-10-28.
      - Also 5 late "Absent slots" values that are valid from 2026-10-01 but recorded today (see the EX13 test in section 5).
   4. mock_studentdata_archived.xlsx
      - 4 rows: 2 for archived attributes (Club membership count, Dormitory block).
      - Expect isSuccess = true, insertedCount = 2 and rejectedRows = the 2 archived rows.
   5. mock_studentdata_invalid.xlsx (and the same rows as mock_studentdata_invalid.csv)
      - 8 rows: 1 valid and 7 invalid.
      - The invalid rows have: an unknown student, an unknown attribute, "abc" as a number, an unknown term, "yes" as a boolean, an empty value, and a bad date.
      - Expect isSuccess = false, 7 errors and nothing inserted (all-or-nothing).
   6. mock_studentdata_invalid_columns.xlsx
      - Columns Student, Data attribute, Score, Term: "Value" is named "Score" and "Valid from" is missing.
      - With the columnMapping above, expect 400 "Mapped column(s) not found in the file: Value, Valid from."
      - Mapping value to "Score" still fails on validFrom: every field must be mapped to a column.
   7. mock_studentdata_student_gmail.csv (optional, any time after file 3)
      - 4 valid rows for student@gmail.com, valid from 2026-11-05 (GPA 6.3, Attendance rate 74, Late submissions 7, Tuition overdue true).
      - Shows that a .csv works with the same columnMapping; Tuition overdue = true hits the "Tuition overdue" indicator.

Step 4 (optional) - account import, signed in as an admin:
   POST /api/Accounts/import (multipart/form-data, file only; POST /api/Accounts/import/preview shows the same checks without writing)
   - Columns: email, fullName, userName, facultyCode, role (comma-separated for several roles), studentCode, academicStatus.
     Staff rows leave studentCode and academicStatus empty; an empty academicStatus on a Student row means enrolled.
   1. accounts_import_valid.xlsx (or accounts_import_valid.csv, same 10 rows)
      - 4 staff (aa.phuongnt, wa.huyld, wo.thanhpv, aa.ngocpt with 2 roles) and 6 students (SE180036, SE190037, SE180038, BA180149, BA190150, BA170151).
      - Expect isSuccess = true and createdCount = 10. Importing the second file after the first gives 10 "already used" errors.
   2. accounts_import_invalid_rows.xlsx
      - 11 rows: row 2 is valid, rows 3-12 each have one problem.
      - Row 3: email student@gmail.com already used. Row 4: email not valid. Row 5: fullName empty and userName aa.hungpt already used.
        Row 6: faculty code IT does not exist. Row 7: role Teacher does not exist. Row 8: Student without studentCode.
        Row 9: academicStatus suspended. Row 10: staff row with a studentCode. Row 11: studentCode SE180003 already used.
        Row 12: the email of row 2 a second time in the file.
      - Expect isSuccess = false, 10 errors and nothing created (all-or-nothing, the valid row 2 is not created either).
   3. accounts_import_invalid_columns.xlsx
      - Columns email, fullName, userName, faculty, studentCode.
      - Expect isSuccess = false with one error on row 1: "Missing column(s): facultyCode, role."

Why the values are not in the SQL script
- STUDENTDATA values are AES-256-GCM encrypted with the student's attribute key, and that key is wrapped with the API master key.
- The import encrypts with whatever master key the running environment uses, so this works for every teammate and for MonsterASP.
- Seeded directly in SQL (no encryption needed):
  - Spring 2026 missing-value rows;
  - Spring 2026 erased rows with their destroyed keys and completed erasure requests;
  - 3 correction requests decided before the erasure (their values were cleared by it).
- After the import:
  - create pending correction requests through POST /api/CorrectionRequests (studentDataId, consentPurposeId, explanation, proposedValue);
  - pending erasures are created automatically when a student withdraws a consent of an attribute that now has a key;
  - indicator flags are raised by the server for every enrolled student whose latest value hits an active indicator.

  - System time:
    - transactionFrom is the moment you ran the import;
    - so as-of any date before your import with timeAxis=system shows no Fall values;
    - as-of today shows the latest recorded value.

  - Use GET /api/StudentData/me, GET /api/StudentProfiles/me and GET /api/StudentData/me/export.

==========
6. REGENERATING
==========

- The data is generated by a script with a fixed random seed, so running it again gives the same ids and values.
- The rows added on 09/11/2026 use fixed name-based ids (uuid5), so they stay the same too.
- Ask Claude to regenerate it after a schema change. Every row is checked against the script's constraints (NOT NULL, CHECK, FK, UNIQUE and the filtered unique indexes) and against the business rules before it is written.
